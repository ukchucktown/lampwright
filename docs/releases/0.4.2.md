# Lampwright 0.4.2 release notes

Lampwright 0.4.2 corrects Disable and Enable for a Skill that the Vercel
`skills` Manager owns. This release adds no command and no option. Lampwright
requires Node.js 20 or newer and supports macOS, Linux, and Windows.

## Disable and Enable of a Vercel-managed Skill

In release 0.4.1, a Suspended Disable of a Vercel-managed Skill moved the
complete artifact set to Disabled Storage and then reported `partial`. The
Vercel lock keeps the record of the Skill, and verification read that record
as a failure. A later Enable returned a plan with no actions, because the plan
read the expected path of the record as an occupied path.

In release 0.4.2, the Disable reports `succeeded` and the Enable restores each
artifact to its original path. If you disabled such a Skill with release
0.4.1, the content is safe in Disabled Storage. Run Enable again with this
release.

## Verification after a Suspended Disable

A Manager record can stay in Inventory after a suspension. A missing Harness
Exposure now passes verification only when a Disabled entry holds the
Installation and no harness can load the Installation. If the Skill is live
under one harness, including a harness that the plan did not name, the report
shows a verification failure.

A Vercel lock can declare an Eve subagent for a project Skill. A declared
Eve subagent is now a Harness Exposure only while the artifact for that
subagent is present. An entry that release 0.4.1 wrote can record a declared
subagent with no artifact. Enable restores such an entry and does not require
that exposure.

## An occupied path blocks the Enable plan

An Enable plan now shows a block when one of the original paths is not free.
Before, some occupants appeared only after you confirmed the plan, and
Execution stopped with `destination-occupied`. Lampwright overwrote no file in
either release.

Two changes give this result:

- Disabled Storage examines each destination of an entry in `previewEnable`.
  The CLI, the terminal UI, and Execution now pass that answer to Planning. A
  `blocked` preview becomes a `configuration-unsafe` block that `--force`
  cannot override. Execution asks again before it changes a file.
- Planning treats the expected path of a Manager record as free only for a
  `broken` record with an absent primary artifact and no canonical path. A
  live Plugin child at that path, or a regular file at that path, blocks the
  plan.

## Interfaces for a host

Three interfaces have new members. Each member is optional, so a host of
release 0.4.1 compiles and runs with no change.

- `planAvailability` takes `enablePreviews` as an optional fourth argument.
- Planning exports `availabilityEnableEntries`, which returns the Disabled
  entries that an Enable intent restores. Each caller previews those entries
  only, so the cost of an Enable plan follows the selection.
- `TuiDependencies` accepts `previewEnable` and `enableEntries`.
  `ExecutionModuleOptions` accepts `availabilityEnableEntries`.

The JSON output and its schema do not change.

## Safety

The safety rules of Lampwright do not change in this release:

- Read-only Inventory scans, terminal browsing, plans, and dry runs create no
  persistent state. The saved theme is the one exception, and only a confirmed
  theme in the picker writes it.
- A scan uses no network access.
- Git-protected content and System Skills stay immutable.
- Enable never overwrites an occupied path.
- Lampwright has no telemetry and does not transmit Inventory, local paths,
  metadata, or search queries.

## Known limits

An Enable plan reads the stored content of each selected Disabled entry, so a
plan for a large selection takes longer than in release 0.4.1.
