# Lampwright 0.5.0 release notes

Lampwright can now give another agent access to a Skill that the Vercel
`skills` Manager already installed. Add agent creates a local directory link,
or a junction on Windows. Each agent reads the same Skill content, and the
Manager keeps its ownership record.

## Preview an agent from the CLI

Run `lampwright scan --json` to find the Installation ID. An eligible
Installation has an `agentDestinations` field that lists the supported agent
IDs and the paths they share. Add agent requires an active canonical
Installation, the directory where the Vercel Manager keeps the Skill.

In this example, replace `ID_FROM_SCAN` with the Installation ID and
`AGENT_ID` with an agent ID from its destinations.

```console
npx lampwright@0.5.0 add-agent installation:ID_FROM_SCAN AGENT_ID --dry-run
```

The preview shows the source, destination, affected agents, and any missing
parent directories. When several agents read the same path, one link makes
the Skill available to all of them. To apply the plan, replace `--dry-run`
with `--yes`.
The CLI also accepts a `logical-skill:` selector when it identifies one
Installation.

## Select several agents in the terminal UI

In Inventory, focus the Skill and press `+`. If it has several eligible
Installations, choose the Scope and path first. Type an agent name to filter
the picker. Press Space to select an agent.
Your selections persist as you search for others.

Press Enter to review all selected agents. If you selected none, Enter
reviews the highlighted agent. The plan shows each distinct destination once.
Press `y` to confirm or Esc to return to the selection.

Lampwright checks every destination before the first write. A conflicting
entry, Git-protected path, or overlap with System Skills or other ownership
boundaries blocks the plan. After a write, a fresh scan verifies the link and
the original Installation. If only some destinations succeed, the report
shows which links exist and why the others failed.

## Public interfaces

The published CLI v1 schema adds `add-agent-plan`, `add-agent-report`, and
`confirmation-required` with `operation: "add-agent"`. For hosts, the root
package exports `createAddAgentModule`. Use its `preview` and `execute`
methods with `AddAgentPlan` and `AddAgentReport` for one agent. For multiple
agents, `previewBatch` returns an `AddAgentBatchPlan` that `executeBatch`
applies. The resulting `AddAgentBatchReport` gives the outcome at each
destination.

For a custom terminal host, `TuiDependencies.addAgent` is optional. If your
host matches every `TuiState.screen` value, add cases for
`add-agent-installation` and `add-agent`. Hosts that match every
`TuiAction.kind` also need cases for `add-agent`, `point-agent`, and
`clear-query`.

On the `add-agent` screen, read the `stage` field of `TuiAddAgentState`.
The `selection` stage tracks the search and checked agents. Review retains
the selection alongside its plan, so Escape can restore it. The `execution`
stage holds the confirmed plan. Success refreshes Inventory, and the
`result` stage holds a report for other outcomes.

After the GitHub `v0.5.0` release and npm publication, run this version with:

```console
npx lampwright@0.5.0
```

See the [CLI guide](../cli.md), [terminal UI guide](../tui.md#add-an-agent),
and [module design](../module-design.md#add-agent) for the full contracts.
