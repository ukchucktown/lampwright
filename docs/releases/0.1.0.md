# Lampwright 0.1.0 release notes

Status: reviewed release-candidate notes. This document describes the intended
`0.1.0` artifact; it does not by itself announce that npm publication has
occurred.

Lampwright 0.1.0 is the first cross-platform release for discovering,
reversibly disabling, enabling, and safely removing AI agent Skills and
complete Plugin boundaries. It requires Node.js 20 or newer and supports macOS,
Linux, and Windows.

After `lampwright@0.1.0` is visible on npm and its release artifact has been
verified, run the exact first release with:

```console
npx lampwright@0.1.0
```

## Supported ecosystems

The built-in Inventory and Adapter catalog covers:

- generic Agent Skills directories and links;
- Vercel `npx skills` Installations and manager records;
- Claude Code standalone Skills and Plugins;
- Codex standalone Skills, protected System Skills, and Plugins; and
- Gemini CLI standalone Skills and extensions.

Codex, Claude Code, and Gemini CLI also have built-in native controls for the
supported Skill and whole-Plugin availability settings. Local, versioned JSONC
Adapters can add bounded discovery and lifecycle support without loading
executable Adapter plugins.

## Safety boundaries

- Inventory is rebuilt from known, configured, or explicitly supplied roots.
  Lampwright does not crawl an entire home directory by default.
- A read-only scan, TUI browse, plan, or dry run creates no Lampwright files or
  persistent state.
- Non-ignored content inside a Git worktree and agent-runtime System Skills are
  immutable, including with `--force`.
- Matching names or hashes alone never merge Skill identities or authorize a
  name-wide change.
- Ordinary remove-all operations exclude Plugins. Plugin-owned Skills cannot be
  individually disabled; a supported availability change controls the complete
  Plugin boundary and leaves all Plugin content installed.
- Hard Dependencies block by default. Soft References warn without silently
  widening the requested operation.
- Lampwright has no telemetry and does not transmit Inventory, local paths,
  metadata, or search queries. Scanning and local Planning require no network
  access.

An available Owner's lifecycle command is a declared mutation boundary rather
than a portable filesystem sandbox. Lampwright uses structured executable and
argument values, disables common telemetry signals, and protects its own paths,
but it cannot roll back arbitrary side effects performed by an external
Manager.

## Disable, Enable, and Disabled Storage

Lampwright prefers a harness-supported Native Disable. When no safe native
control exists, a Suspended Disable is available only if Planning can authorize
the complete artifact set. A supported Manager-owned suspension moves every
declared discovery artifact while preserving the Manager record.

Suspended content enters Disabled Storage, a separate non-expiring recovery
store. It never appears in Trash and has no retention purge. Native Disable
creates no Disabled Storage entry because the Installation remains in place.

Enable restores a suspended set to every exact original path. It never
overwrites an occupied or changed destination. If a Manager recreates a path
while its Skill is suspended, the replacement is reported as a conflict and the
stored content remains available for recovery.

## Removal, fallback, and Trash

Lampwright prefers Managed Removal through an available Owner. A missing or
failed Manager never triggers Brute-force Removal silently. After the failure,
Lampwright rescans and may offer a new fallback Removal Plan that requires a
separate Brute-force confirmation. Failed actions stop their dependents while
independent branches may continue.

Brute-force Removal moves filesystem artifacts into Quarantine, presented as
Trash, instead of deleting them permanently. Trash entries retain integrity,
ownership, original-location, and restoration evidence. They are retained for
30 days by default and may be restored or explicitly purged. Expired Trash is
purged only through an explicit purge selection; read-only use never purges.

Restore does not overwrite an occupied destination without an explicit safe
resolution and rechecks Git protection. Purge is permanent. A Managed Removal
is audited but is not automatically restorable by Lampwright unless the Owner
itself provides a restoration operation.

## Recovery expectations

Every mutation is replanned from fresh live evidence and ends with a rescan.
Reports distinguish succeeded, partial, failed, blocked, unchanged, and
unresolved outcomes rather than treating an attempted action as success.

Quarantine and Disabled Storage use integrity-checked manifests, transaction
journals, and path claims. Recovery runs at the start of a later mutating call;
read-only listing and preview do not recover or change state. After an
interruption, collision, integrity failure, stale plan, or race:

1. leave the stored manifests, journals, claims, and payloads untouched;
2. repair only the reported external condition;
3. rescan and review a fresh plan; and
4. retry the matching Lampwright mutation.

Lampwright fails closed when it cannot prove ownership, integrity, path
containment, or a safe destination. Do not manually move or edit content inside
Quarantine or Disabled Storage.

## Known limitations

- Capabilities compiled into an agent executable have no filesystem artifact
  and are outside Inventory by construction. Claude Code runtime capabilities
  therefore do not appear as fabricated rows; Codex filesystem System Skills
  remain visible but protected.
- Plugin caches, source repositories, vendored files, and unknown `SKILL.md`
  files are not independently removable Installations without stronger
  evidence.
- Lampwright does not install agent runtimes, Managers, Plugins, or missing
  package runners. An exact-version ephemeral package runner may use the network
  only after its download/cache behavior and trust tuple are disclosed and
  approved.
- Remote and executable Adapters, a public Adapter registry, full-home deep
  scans, and edits to Git-protected project source are outside version 1.
- The TUI selects Logical Skills, declared Installation Groups, and complete
  non-default Plugin boundaries. Selecting one physical Installation is
  available through the CLI rather than the TUI.
- External Manager operations do not receive transactional rollback, and
  Lampwright does not promise an exact token saving from disabling a Skill.
