# Lampwright 0.3.0 release notes

Lampwright 0.3.0 makes the Inventory scan independent of the network and makes
the terminal interface easier to read. It also protects the Skills that Claude
synchronizes. Lampwright requires Node.js 20 or newer and supports macOS, Linux,
and Windows.

## Scan without the network

A scan no longer runs the Codex executable. Earlier releases ran
`codex plugin list --json` in each scan, and Codex contacts a remote plugin
catalog each time that command runs. On a slow network, the terminal interface
stayed on the scan screen until Codex stopped the request. With a stalled
connection, that delay was about 30 seconds.

Lampwright now reads Codex Plugins from the Codex `config.toml` file and the
Codex plugin cache. The start time does not depend on the network.

This change also corrects the Codex Plugin list. In earlier releases, a remote
plugin that the Codex desktop app enabled made Lampwright reject the full Codex
listing, and no Codex Plugin showed in the Inventory. Lampwright now shows the
Codex Plugins that have a Plugin table in the configuration file. The remote
plugins from the Codex desktop app are not Lampwright targets.

Lampwright follows a symbolic link at the Codex configuration path. Managed
Removal stays unavailable for a linked configuration file.

## One row for identical copies

You can copy one Skill directory into the skill roots of two or more agent
harnesses. Earlier releases showed one row for each copy in the
`No shared source` section.

The terminal interface now shows one row for copies that have the same name and
identical content. The row lists all agents and all paths. When you remove,
disable, or enable from that row, the review screen lists each copy as a
separate target.

Two Skills with the same name and different content stay in separate rows. The
`scan --json` output still contains one record for each copy.

## Claude synced Skills are System Skills

Claude synchronizes a set of Skills into the `skills/synced` directory of its
configuration directory. Earlier releases listed these Skills as manual
Installations that you could remove.

Lampwright now shows them in the `System skills` section with the source that
the synced manifest declares. They are read-only: no Removal, Disable, Enable,
or Update plan can contain them, and `--force` does not change that rule.

In the `scan --json` output, these Skills move from `installations` to
`otherFindings` with the classification `system-skill`. A script that reads
`installations` no longer receives them.

## Safety boundaries

Lampwright keeps these existing safety rules:

- Read-only Inventory scans, terminal browsing, plans, and dry runs create no
  persistent state.
- A scan uses no network access.
- Git-protected content and System Skills stay immutable.
- Lampwright does not replace a failed managed operation with a filesystem
  change.
- Lampwright has no telemetry and does not transmit Inventory, local paths,
  metadata, or search queries.

## Known limits

Lampwright reads the Codex files directly. If a later Codex version changes the
layout of its configuration file or its plugin cache, the Codex Plugin list can
be wrong until Lampwright follows the change.

Lampwright does not check that a configured Codex marketplace still lists a
Plugin. A Plugin that Codex no longer lists can show in the Inventory, and its
Managed Removal can then fail.

When the manifest of a Claude synced bucket is absent or not valid, the Skills
in that bucket show as ordinary Installations.

The Disabled view of the terminal interface does not combine identical copies.

```console
npx lampwright@0.3.0
```
