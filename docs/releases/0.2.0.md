# Lampwright 0.2.0 release notes

Lampwright 0.2.0 adds targeted Update support for Owner-managed Skills and
Plugins. It also makes the terminal interface and package documentation easier
to use. Lampwright requires Node.js 20 or newer and supports macOS, Linux, and
Windows.

## Targeted Update

Lampwright can now ask an existing Owner to update a selected target. This
release supports these Update operations:

- Vercel-managed Skills from a recorded source
- Claude Code Plugins from their recorded marketplace
- Gemini CLI extensions from their recorded source.

The terminal interface and the non-interactive CLI show the planned Owner
operation before the Update. Lampwright then rescans the live Inventory and
reports how many Skills changed or stayed unchanged.

An Update preserves the existing target boundary and each supported app's
enabled or disabled setting. Lampwright does not replace a failed managed
operation with a filesystem change.

## Reversible availability

Lampwright keeps its reversible disable and enable controls for standalone
Skills and complete supported Plugin boundaries. Native harness controls keep
the content in place. Disabled Storage retains supported content when a native
control is not available.

This control lets you keep a large Skill collection installed while you expose
only the Skills that you need. A smaller active set can decrease the Skill
metadata that a harness loads into model context. The actual token savings
depend on the harness.

## Terminal interface

The Update review and result screens now use concise, consistent language. The
result screen summarizes each source with the counts of updated and unchanged
Skills. When you return to Inventory, Lampwright clears the previous selection
and result details.

The README now includes an Inventory screenshot and a clearer feature summary.
The npm package metadata also includes search terms for AI Skills, Skill
management, supported harnesses, and terminal tools.

## Safety boundaries

Lampwright keeps these existing safety rules:

- Read-only Inventory scans, terminal browsing, plans, and dry runs create no
  persistent state.
- Git-protected content and System Skills stay immutable.
- Update operations use the current Owner and the recorded source.
- Lampwright requests approval before an Owner operation that can download a
  package or contact a remote service.
- Lampwright does not promise automatic rollback for an external Owner
  operation.
- Lampwright has no telemetry and does not transmit Inventory, local paths,
  metadata, or search queries.

## Known limits

Targeted Update is available only when Lampwright has sufficient Owner and
source evidence. Other targets stay visible but do not offer Update. External
Owner operations can change files outside Lampwright's direct control and do
not have transactional rollback.

After the GitHub `v0.2.0` release is available, run this version with:

```console
npx lampwright@0.2.0
```
